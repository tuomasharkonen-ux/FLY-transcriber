# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
uv run fly-transcriber                       # run the menubar app (dashboard at http://127.0.0.1:8756/)
uv run pytest                                # all tests
uv run pytest tests/test_core.py -k slugify  # single test / subset
uv run python scripts/dashboard_preview.py   # UI on :8757 ($PORT) with fake data; popover at /popover.html
uv run fly-transcriber install-agent <dir>   # write CLAUDE.md + the agent skill into an existing project folder
uv run fly-transcriber install-launcher      # FLY.app into /Applications, else ~/Applications (uninstall-launcher removes it)
uv run fly-transcriber warmup                # apply ownscribe config, prefetch Whisper models (installer runs this)
sh scripts/package_speaker_model.sh          # build dist/speaker-diarization-community-1.tar.gz from your HF cache
uv run --with playwright python scripts/make_demo_gif.py  # re-render docs/demo.gif from the popover UI (Chrome + ffmpeg)
sh -n install.sh                             # syntax-check the installer (it installs for real; don't run it casually)
```

No linter or type-checker is configured. CI (`.github/workflows/`) runs the tests on macOS for every push, and weekly checks that a fresh install of the pinned ownscribe still loads the local speaker model and still has the hooks `mlx_launch.py` patches. Runtime needs macOS 14.2+ on Apple Silicon and `ownscribe` 0.15.x with mlx-whisper (`uv tool install 'ownscribe>=0.15,<0.16' --with mlx-whisper==0.4.3`; without it, transcription falls back to the CPU).

Naming: the product is **FLY-transcriber** (repo `tuomasharkonen-ux/FLY-transcriber`, dashboard brand "FLY — Faithful Logger of Yapping"); the Python package/command/dirs are lowercase `fly-transcriber` / `fly_transcriber`. It was called `local-meeting-recorder` until 2026-09-29; the local checkout directory still has that name.

## What this is

A macOS menubar front-end (PyObjC, accessory app, no Dock icon) that drives the **ownscribe** CLI to record → transcribe (`large-v3`) → diarize (pyannote via whisperx), then saves a speaker-labelled transcript into a project folder for another agent to write notes from. **There is no summarization, by design** — the local model fabricated decisions and drifted languages. Don't reintroduce it; effort goes into transcript quality. Likewise **no vocabulary hints** (removed in v0.5.0): names and jargon are corrected by the receiving agent via the `fly-summarise` skill, which knows the project. The README explains the reasoning behind most design choices; read it before changing behaviour.

## Architecture

- **`recorder.py`** — runs ownscribe as a subprocess (never imported; the CLI is the stable contract). Stop = `SIGINT`, which ends capture and *starts* processing (a handoff, not a kill). A background thread pumps stdout and infers `Phase` from log markers ("Transcribing", "Diarizing", …), only ever advancing forward. Prefers `ownscribe` on PATH over `uvx` because the uvx launcher complicates signalling. `ownscribe_command` picks the engine: with `engine = "mlx"` (default) and `mlx_whisper` importable in ownscribe's env (found via the `ownscribe` script's shebang), it runs `<ownscribe's python> -P mlx_launch.py <args>` instead; otherwise plain ownscribe (faster-whisper). `progress.py` keeps timings per engine.
- **`mlx_launch.py`** — runs on *ownscribe's* Python (so: no FLY imports; `-P` keeps FLY's modules off its path). Replaces `WhisperXTranscriber._load_model` with one returning `MlxModel`, whose `.transcribe(audio, …)` returns whisperx's `{segments, language}` shape, then calls ownscribe's CLI — capture, alignment, diarization, output and log markers are all still ownscribe's. ~4× faster transcription on the GPU (25-min meeting: 228 s from stop vs 560 s). `condition_on_previous_text=False` is essential: with it on, large-v3 looped phrases and dropped sentences. Weights `mlx-community/whisper-<model>-mlx` resolve cache-first (offline). Depends on ownscribe internals (`_load_model` sets `self._model`; `_transcribe_inner` calls `self._model.transcribe(`) — checked by `upstream.yml`; re-verify on an ownscribe upgrade. Follow-up: an ownscribe PR for a `transcription.backend` setting would let this go.
- **`config.py`** — `settings.toml` in `~/.config/fly-transcriber/` is the source of truth. `~/.config/ownscribe/config.toml` is *generated* from it before every recording, because the HF token has no CLI flag; it starts with `GENERATED_MARKER`, and only a file without it (hand-written, or ownscribe's default) gets a `.bak-*` snapshot first. Written `0600` from the first byte (`write_private`); the config dirs and the recordings folder are made `0700` (`ensure_private_dir`), since macOS home folders are readable by other local accounts. The token itself lives in a separate `hf_token` file (or `$HF_TOKEN`), never in settings.
- **`diarization.py`** — the speaker model, local or hub. **Turnkey path (no HF account):** the installer puts a copy of `pyannote/speaker-diarization-community-1` (CC-BY-4.0, gate auto-approved) at `MODELS_DIR/<repo id>/` (`~/.local/share/fly-transcriber/models/`). pyannote's `Pipeline.from_pretrained` treats a checkpoint name that `os.path.isdir()` as local *before* the hub, relative to cwd, so `recorder.py` launches ownscribe with `cwd=MODELS_DIR` and whisperx's hard-coded hub name resolves to the local copy. ownscribe skips diarization without a token, so `config.py` writes `LOCAL_MODEL_TOKEN` as a placeholder (never sent). This relies on ownscribe/pyannote internals — hence the ownscribe pin in `install.sh`; re-verify on upgrade (a fake-token run from `MODELS_DIR` must diarize, from elsewhere must 401). **Hub path (fallback, real token):** ownscribe exits 0 with an unlabelled transcript when the gated model is unreachable, so `check_diarization` probes `HEAD /resolve/main/config.yaml` (the metadata API returns 200 even when not granted). The gate that matters is `community-1`, not `3.1`.
- **`transcript.py`** — builds `Turn`s from ownscribe's **JSON**, not its markdown: markdown labels whole segments, JSON keeps whisperx's per-word speaker, so segments are split where the word speaker changes (single-word flips absorbed). Markdown parsing is a fallback. `"Unknown"` is ownscribe's gap marker, not a speaker.
- **`meetings.py`** — reads ownscribe output dirs `<output>/YYYY-MM-DD_HHMM[_slug]/` into `Meeting` objects.
- **`projects.py` / `filing.py`** — a project is a watched folder with `naming` (`vault`|`timestamp`) and `frontmatter` (`obsidian`|`generic`) styles. Saving writes one markdown file with `status: raw` + a banner (plus a speaker-attribution caution when diarized); speaker renaming applies only to the saved copy (the original under `~/ownscribe` keeps `SPEAKER_NN`). Adding a project from the dashboard goes `plan_project` → shown to the user (every folder/file, new or kept) → `apply_plan`; the plan is computed server-side on every form change so the preview is exactly what happens. `create_project`, `apply_plan` and the `install-agent` subcommand (all via `install_agent_files`) write a `CLAUDE.md` plus the bundled `fly-summarise` skill (`skills/…/SKILL.md`, shipped as package data, installed to `.claude/skills/`) and never overwrites existing ones.
- **`state.py`** — JSON ledger (`state.json`) of what was saved where plus user-entered titles/names/skipped, keyed by meeting dir *name*. `awaiting_filing` drives the menubar's "Ready to save (n)" and the dashboard's auto-opened save form. Atomic writes; a corrupt file degrades to "nothing saved".
- **`server.py`** — stdlib `ThreadingHTTPServer` on 127.0.0.1:8756, no auth, no framework. The `Api` object of callbacks is its only coupling to the app, so tests (and `scripts/dashboard_preview.py`) use a stub. `/api/record` toggles recording; the app hops it to the main thread with `call_on_main` because starting can show alerts.
- **`shell.py`** — all native UI, PyObjC directly (rumps was dropped: it only does menus). A status item drawing the FLY glyph in code (template image; red tint + timer while recording, SF `waveform` while processing, count of unfiled recordings as the title). Left-click opens an `NSPopover` whose content is a **transparent** `WKWebView` of `popover.html`, so the system popover material (Liquid Glass on macOS 26) is the background; right-/Control-click shows a native menu built fresh from a spec. The full dashboard opens in an `NSWindow` with its own `WKWebView`, not a browser. Pages post `{type: resize|close|open}` to `window.webkit.messageHandlers.fly`. A hidden main menu exists only so ⌘C/⌘V/⌘A/⌘Z/⌘W reach the web views. `AppHelper.installMachInterrupt()` must be called explicitly (runEventLoop skips it when NSApplication already exists). `FLY_DEBUG=1` makes the web views inspectable from Safari.
- **`static/`** — the UI, branded **FLY** — Faithful Logger of Yapping (name in `BRAND` in `app.js` and `<title>`; the logo (a microphone with fly wings) is drawn twice, in `Logo` in `app.js` and in `favicon.svg`, keep them in sync; `_fly_glyph` in `shell.py` is a third, monochrome copy). Two entry points share `common.js` (API helper, primitives, status logic, `useFilingForm` + `FilingFields`): `app.js` is the dashboard (window/browser), `popover.js` + `popover.css` the menubar panel (record control, latest 6 recordings, inline saving). `popover.css` overrides the semantic tokens with translucent glass tints — the page has no background of its own. Preact + htm, vendored as one ES module in `static/vendor/` — no build step, no npm, works offline; keep it that way. Hash routes: `#/` list, `#/r/<meeting-dir>` full view, `#/settings` (`#/settings/add-project` opens project setup), `#/save/<meeting-dir>[/new|existing|add]` (the popover hands saving over here when a project must be set up first, because the folder picker would close the transient popover). Both poll `/api/state` every second; form components keep their own local state so polling never clobbers typing (settings follow the server only until edited). Colour tokens at the top of `style.css` are two-tier: palette scales (twilight-indigo, eggshell, burnt-peach, muted-teal, apricot-cream, plus ink greys and two extra speaker hues) and semantic tokens (`--brand`, `--text-2`, `--ok-soft`, …). Components use only semantic tokens; dark mode overrides only the semantic tier (it inverts the pair: indigo ground, eggshell primary). The logo has its own `--logo-*` tokens and looks the same in both themes. Brand colours also live outside `style.css`: `favicon.svg` (then `scripts/make_icon.py` for `FLY.icns`), the deck's own `:root`, and the demo wallpaper in `scripts/readme_demo.js`. Keep text pairs at WCAG AA.
- **`app.py`** — thin layer wiring it together. The recorder and HTTP server run on background threads; **all AppKit UI mutation happens on the main thread** via the 1-second `_tick` timer (flags/events set from other threads) or `call_on_main`.
- **`install.sh`** — the one-line installer, for a fresh Mac with nothing on it: checks macOS 14.2+/arm64, installs uv, pinned ownscribe (`--with` pinned `MLX_WHISPER`) and the app as `uv tool`s (the app from GitHub's source archive of the newest `v*` tag, found via the tags API: no git, which on a fresh Mac is a stub that prompts for the developer tools; no Homebrew), downloads the speaker model from the `speaker-model-v1` GitHub release (verified per file against `MODEL_SHA256`; a failed download warns and falls back to the HF-token path), runs `fly-transcriber warmup` (~3 GB Whisper), and adds a LaunchAgent login item (`io.github.fly-transcriber`). It is written for people opening Terminal for the first time: an intro saying why the 3 GB download exists (local models = offline), a now/later question for it (read from `/dev/tty`; no terminal → now), numbered `[n/5]` steps each with a dimmed `detail` line naming exactly what is installed where (for technical readers), quiet `uv` output, and a closing checklist. Flags: `--no-login-item`, `--warmup`/`--no-warmup` (skip the question), `--uninstall`. The body runs inside `main()`, called on the last line: piped into `sh`, the script is stdin, and a command reading stdin (`brew install` did) swallowed the rest and stopped the install silently. An EXIT trap tells the user it didn't finish. Login-item launches get launchd's minimal PATH, so `app.main` appends `~/.local/bin` and Homebrew dirs; if there is still no `ffmpeg`, it links the one bundled with the `imageio-ffmpeg` dependency into `~/.local/share/fly-transcriber/bin/` (ownscribe finds ffmpeg by name on PATH). `warmup` applies this app's ownscribe config first because ownscribe's own default would also download a summarization LLM.
- **`scripts/package_speaker_model.sh`** — builds the release archive (+ CC-BY `NOTICE.md`) from the maintainer's HF cache into gitignored `dist/`. If the model files change, update `MODEL_SHA256` in `install.sh`.
- **`launcher.py`** — builds `FLY.app`, a stub bundle (shell script that starts `~/.local/bin/fly-transcriber --show` *detached* and exits — if the exec'd process is the one LaunchServices launched for the bundle, macOS 26 never shows the menubar icon; the cause is unknown, `LSUIElement`, icon from `assets/FLY.icns`, ad-hoc signed) so the app can be opened from Spotlight after quitting. Tries `/Applications` (admin users can write there without `sudo`), falls back to `~/Applications`; removal only touches a bundle whose `CFBundleIdentifier` is ours. It is a *launcher*, not the app's identity: the running process is the `uv` tool's Python, so macOS permission prompts are not attributed to "FLY". `shell.activate()` uses `activateIgnoringOtherApps_` because plain `activate()` is ignored when a detached child starts while another app is frontmost. `app.main` handles relaunching: `server.show_running_instance` POSTs `/api/show` to the running instance (which opens the dashboard window) and exits; `--show` also opens the dashboard on a cold start, because the menubar icon can hide behind the notch. The shell's delegate also handles the macOS "reopen" event. `scripts/make_icon.py` regenerates `FLY.icns` from `favicon.svg`.
- **`dialogs.py`** — the native folder picker (`choose_folder`, for project setup; a web page can't learn a folder's path) and the HF-token prompt go through `osascript`, out-of-process: an `NSAlert` text field can't take focus in an accessory app and blocks the main thread. Everything else is typed in the web UI.

Tested logic lives in the non-UI modules; `app.py` and `shell.py` have no tests. The web UI can be checked in a browser via `dashboard_preview.py`; the native shell (icon, popover glass, focus, key equivalents) can only be checked by running the app. Tests are all in `tests/test_core.py`.

## Constraints to keep in mind

- ownscribe's CLI args are fixed at launch, so anything that changes transcription (model, language, engine) must be set before recording; speaker names can only be mapped after diarization.
- `notes/` and `hf_token` are gitignored — they contain meeting content / secrets. Never commit transcripts.
- The repo is meant to be public: keep real client, project and colleague names out of code, tests, fixtures and docs (use Acme/Globex, Aino/Mikko/Sara, Alex/Sam).

## Releases and notes

- `main` is work in progress; the installer installs the newest `v*` tag (`FLY_VERSION=vX.Y.Z` overrides), so a release is: bump `version` in `pyproject.toml`, `uv lock`, commit, tag, `gh release create` (steps in the README's Releasing section). `install.sh` itself is fetched from `main`, so changes to it are live on push and must work with the latest release. The speaker model ships as its own release, `speaker-model-v1` (built by `scripts/package_speaker_model.sh`); keep its tag from starting with `v` so it is never mistaken for an app release.
- The local server accepts only its own pages: `Host` must be loopback, a present `Origin` must be its own, POSTs must be JSON (`server._allowed`), and no other site may frame them (`frame-ancestors`, against clickjacking). Keep that when adding routes; any web page the user visits can reach the port. Endpoints taking a meeting name resolve it through `_meeting_directory` in `app.py`.
- Frontmatter values typed by people (titles, names, tags) go through `filing.yaml_str`, which quotes anything YAML would misread.
- Follow-up: send ownscribe a PR adding a `diarization.model` setting (local path, no token required) so the cwd trick in `recorder.py` can go.
- `docs/how-it-works.html` is an animated slide deck explaining the product; keep it in step with the README when behaviour changes. `docs/demo.gif` is rendered from the real popover UI by `scripts/make_demo_gif.py` driving the scripted story in `scripts/readme_demo.js` (fake API, stand-in desktop); re-render it when the popover changes.
